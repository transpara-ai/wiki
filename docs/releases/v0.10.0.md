# v0.10.0

Adds a private terminology workspace for the proposed Transpara technical-English
workflow. Humans can inspect candidate terms, source contexts, the Transpara
Dictionary, and existing regular-English decisions. A Human can download a draft
classification proposal bound to the displayed dictionary digest and context
hashes of the shown observations. A count identifies any undisplayed evidence;
its contexts are excluded from the draft. The proposal does not change a
dictionary or approve a term.

Administrators opt in by setting `TRANSPARA_TERMINOLOGY_SNAPSHOT` to an absolute
path to a JSON export from the separate technical-English tool. The new snapshot
API uses the existing private authoring access check and reads one fixed local
file. It accepts no user paths or remote URLs. Company-internal and public builds
omit the workspace assets and navigation; the API also rejects requests outside
the authoring profile. No dictionary publication or approval endpoint is added.

ASD-STE100 stays external. This release contains no ASD reference content and
makes no conformance claim. Existing authoring credentials do not grant authority
to approve terminology. The Transpara Dictionary remains a Human-owned document.
See the [workspace manual and technical reference](../terminology-workspace.md)
for setup, snapshot contracts, the proposal review steps, and implementation limits.

This compatible new capability raises the minor application version. Existing
repositories are not enrolled automatically. Without a configured snapshot, the
workspace explains the missing configuration. Older exports without context
hashes remain readable but need a fresh scan before proposal download.

The adapter limits each snapshot read to 1 MiB and uses both existing private
evidence reader prerequisites before reading it. Whole raw and decoded JSON
pass through the existing evidence quarantine. A remote shared token alone
does not grant read access. The operator must authorize the curated export for
the existing internal curator cohort. The browser renders at most 100
matching candidates, 10 source observations for the selected candidate, and 100
dictionary or ledger entries per view. These are implementation bounds, not
measured capacity guarantees; deployment acceptance should measure representative
snapshot size, response time, and browser responsiveness.

Local validation covers adapter schema and file boundaries, authoring/profile
access, refusal of mutation requests, hostile source text, digest-bound draft
downloads, stale and missing exports, keyboard access, and narrow screens. The
real core-tool snapshot was also loaded through the Python API and browser.
The first full verification run passed its unit and DOM checks and 72 browser
cases; four existing time-zone cases failed because the isolated worktree lacked
the ignored refresh-status fixture. With a byte-identical copy of the canonical
checkout's existing fixture, all ten targeted terminology and time-zone cases
passed. The isolated shadow rebuild was byte-equivalent, retained all baseline
routes, resolved local links, and passed all 77 browser cases. The adapter's five
tests, 16 release tests, release metadata check, and CI YAML syntax check passed.
The existing CI job now runs the adapter and terminology asset syntax checks.
This note does not claim a subsequent full verification command, CI execution,
publication, deployment, or production approval qualification.
