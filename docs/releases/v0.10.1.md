# v0.10.1

Fixes the shared-provider image build when the build context has restrictive
file permissions. The image gives UID 1000 execute access to the three provider
binaries and read access to the provider requirements. The requirements file and
its directory are root-owned and read-only for the provider process. See
[Wiki issue #119](https://github.com/transpara-ai/wiki/issues/119).

A local Docker test built the old and corrected recipes with stub binaries
at mode `0700` and the requirements file at mode `0600`. The old image
denied UID 1000 access. The corrected image ran the three stubs and the
sandbox symlink and read the requirements as UID 1000, with no write
access to the policy file or its directory. The five provider unit tests also
passed. The fixture tests file access. Native subscription authentication
is verified separately by the provider's operational monitor.

The change sets modes during the image build and adds no startup work. The
permissions take effect when the provider is rebuilt and replaced through the
existing deployment procedure. The example Compose file pins an older image,
so select the rebuilt image when updating the service.
